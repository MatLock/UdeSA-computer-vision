# Change Proposal: Automated Google Ads Positioning

## Why

The project today generates **product-descriptive attributes from an image**
(`product_type`, `color`, apparel attributes, `title`, `description`). This covers
only the first of four layers required to automate positioning on Google:

```
Layer 1 · Product content          ← ~70% done today
Layer 2 · Google Merchant feed     ← missing
Layer 3 · Publishing / sync        ← missing
Layer 4 · Positioning / optimization ← missing
```

To automate positioning we must (a) complete the Google Merchant product schema,
(b) validate it against Google's spec, (c) publish it to Merchant Center, and
(d) create and continuously optimize Google Ads campaigns.

## What Changes

This proposal introduces **four new capabilities** (all greenfield, nothing modified):

1. **product-enrichment** — complete the fields that are *inferable* from the image
   and existing tags (improved title, gender, material, pattern, Google category).
2. **merchant-feed** — map enriched products to the Google Merchant schema and
   validate every row before publishing (business fields come from the user's CSV).
3. **merchant-publishing** — manage credentials and upload the validated feed to a
   Merchant Center (test or production) account via the Merchant API.
4. **ads-optimization** — create/update Shopping or Performance Max campaigns via the
   Google Ads API, pull metrics, and run an optimization loop.

### Key design decision: inferable vs business fields

| Field type | Examples | Source |
|---|---|---|
| Inferable | `color`, `gender`, `material`, `pattern`, `google_product_category`, improved `title`/`description` | Generated by the pipeline (image + tags + LLM) |
| Business | `price`, `gtin`, `availability`, `link`, `brand` | **Must be supplied by the user's CSV** — never invented |

A feed row is only publishable when both sets are present and valid.

## Impact

- Affected areas: new modules under `deep-tagger-api` (or a new `positioner`
  package); extends the existing `img-puller` enrichment pattern.
- External dependencies added: Google Merchant API client, Google Ads API client,
  service-account auth.
- No existing behavior is modified; the current `/predict-image` endpoint and the
  `img-puller` CLI keep working unchanged.
- Requires Google Cloud project + test accounts (see `requirements.md`).

## Non-Goals

- Replacing the existing CV models (TinyVGG, ResNet, BLIP, K-Means) — they are reused.
- Guaranteeing feed approval for invented business data (test accounts only).
- Real ad spend during development (handled via test accounts; see `requirements.md`).
